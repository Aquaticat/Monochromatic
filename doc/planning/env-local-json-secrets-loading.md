# Plan: load search-fetch secrets from `.env.local.json` without mise

## Purpose and how to review

This is a design proposal under review.
No implementation code exists and implementation is deliberately on hold.
Read the "Reviewer reading list" section for the files that ground each decision,
then judge "Settled decisions" and "Rejected alternatives".
Object per decision id (`D1`, `D2`, ...), naming the alternative you prefer.

Design was confirmed with the requester on 2026-10-18 in a structured interview;
question ids in parentheses trace each decision back to that interview.

## Problem

Local secrets live in an age-encrypted `.env.local.json` at the repo root
(`doc/philosophy/secrets.md`, section "Approach: mise-native encryption, not a dedicated secrets tool").
Only mise loads it,
through the generated `_.file` directive
(`mise.toml:1347-1353`,
generated by `file-enforcer.config.ts:656-667`).
When mise is not in the launch path,
nothing reads that store.

search-fetch resolves its two provider keys,
`EXA_API_KEY` and `LINKUP_API_KEY`
(`package/agent-harness-shared/search-fetch/src/config-constants.ts:12,17`),
from `process.env` or from plaintext `exaApiKey`/`linkupApiKey` fields in
`~/.pi/agent/extensions/pi-search-fetch.json`
(filename constant `package/agent-harness-shared/search-fetch/src/config-constants.ts:31`).
Neither key is present in `.env.local.json` today.

The dsh launch path shows why env injection cannot be the only channel:
the harness scrub drops env names matching `KEY|PASSWORD|SECRET|TOKEN` plus `DSH_*`
from the spawned MCP server
(`package/dsh-plugin/search-fetch/cordis.patch.yml:10-15`),
so those keys reach the server today only through the pi config file on disk.

The practical win is one secrets home instead of a second plaintext key file,
plus loading that works with no mise in the loop.
The dsh path itself keeps working either way.

## Requirements

- R1: search-fetch resolves both provider keys from the repo's `.env.local.json` with mise absent.
- R2: the loader is encrypted-only, matching `doc/philosophy/secrets.md` ("The loader is encrypted-only").
- R3: no hydrated key enters `process.env` inside search-fetch, so spawned subprocesses (`gh`) inherit nothing new.
- R4: the loading mechanism is a generic module other packages can adopt.
- R5: the two key values migrate out of `pi-search-fetch.json`; its key fields become deprecated.
- R6: tests create disposable fixtures and commit no key material.

## Settled decisions

- D1 (Q1): the mechanism ships as generic `package/module/env-local-json`;
  search-fetch is its first consumer.
- D2 (Q2, Q10): precedence is `process.env` > `.env.local.json` > `pi-search-fetch.json`;
  the file fills only absent-or-empty env values.
- D3 (Q3): discovery is `ENV_LOCAL_JSON_PATH` first, else the closest `.env.local.json`
  walking up from `cwd` to the filesystem root.
- D4 (Q4): lazy strictness.
  Missing file or key means absent;
  a present-but-unreadable file throws only when a requested key is missing from env.
- D5 (Q5, Q12): decryption shells out to `sops` found on `PATH` only;
  absence is a named error with remediation.
- D6 (Q11): identity chain is `SOPS_AGE_KEY_FILE`, then `~/.config/sops/age/keys.txt`
  (honoring `XDG_CONFIG_HOME`), then `~/.config/mise/age.txt`;
  when the variable is unset the module supplies the mise path to sops, so no key moves.
- D7 (Q6, Q8): async pure reader returning the secret record plus a `hydrate` helper for
  consumers wanting mise parity;
  in-memory cache with an explicit reload;
  plaintext is never written to disk.
- D8 (Q9): decrypted top-level scalars are coerced to strings;
  nested objects and arrays are rejected with a named error.
- D9 (Q13): encrypted-only.
  A file without sops metadata is rejected with a named error;
  `doc/philosophy/secrets.md` stays as written.
- D10 (Q14): naming is `package/module/env-local-json` with override variable `ENV_LOCAL_JSON_PATH`.
- D11 (Q15): search-fetch merges the reader's values into the env object `loadLinkupConfig`
  already receives and never mutates `process.env`.
- D12 (Q16): migration is automated with verify-then-delete:
  write both keys into `.env.local.json` through non-interactive sops
  (secret values never on argv), decrypt and compare, then delete `exaApiKey`/`linkupApiKey`
  from the pi config and keep `blocklist`.
- D13 (Q17): tests generate fixtures at runtime in a temp dir
  (`age-keygen` identity, `sops --encrypt` file, `SOPS_AGE_KEY_FILE` pointed at the identity).
- D14: the `sops` metadata key of a decrypted file is stripped and never exported as a secret name.
- D15 (Q10): deprecated pi key fields stay honored as the lowest-precedence source,
  with a once-per-process warning naming the new home;
  field removal is a later change.
- D16: values never appear in logs or errors, only key names (matches `redact = true` in `mise.toml:1353`).
- D17: the plaintext-rejection guard test is proven to fail before it is trusted
  (guard removed, rebuilt, run, restored), and the doc updates listed under "Change surface" ship with the code.

Provisional exported names, open to objection:
`readEnvLocalJson`, `hydrateEnvLocalJson`, `reloadEnvLocalJsonCache`,
and error classes `EnvLocalJsonMissingIdentityError`, `EnvLocalJsonDecryptError`, `EnvLocalJsonShapeError`.

## Rejected alternatives

- Hydrating `process.env` inside search-fetch (Q15):
  spawned subprocesses would inherit keys, against the dsh scrub intent.
- Accepting plaintext JSON (Q7, Q13):
  contradicts "The loader is encrypted-only" in `doc/philosophy/secrets.md`.
- Pure-JS sops and age decryption (Q5):
  an unreviewed crypto surface to maintain for one file format.
- Scanning mise's install layout for the `sops` binary (Q12):
  hardcodes one toolchain's private paths into a generic module.
- Checked-in encrypted fixture with a throwaway identity (Q17):
  commits key-shaped material to git history.
- Additive-only key migration (Q10):
  leaves duplicate plaintext secrets in the pi config until an unscheduled manual step.
- Flattening nested JSON values (Q9):
  an invented separator convention with collisions and no round trip.
- Path fixed relative to the installed package (Q3):
  breaks the moment the package runs outside this monorepo.
- Throwing on any unreadable file (Q4):
  breaks keyless operations such as plain `web_fetch` on a file nothing needed.

  and `mise.toml` mirroring sibling modules.

  for the D15 deprecation warning.

  (`package/agent-harness-shared/search-fetch/src/client-http.ts:205`, `src/exa-http.ts`),
  so it names `.env.local.json` too.

  (user credential files outside the repo, mutated only per that decision).
- Docs: `README.md` of the new module and of the mcp, pi-plugin, and dsh-plugin packages;
  `doc/philosophy/secrets.md` gains the two key names in its store inventory;
  `doc/planning/mise-removal-coverage.md` gains one line naming this module as owner of
  file reading and decryption.
