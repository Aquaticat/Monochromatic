## Modules

- `src/native/auto_push_branch_key.rs` (+ `_tests.rs`, 7 tests).
  Reproduces `encodeBranchKey` / `decodeBranchKey`.
  Its incumbent fixture pairs were generated by Node 26 running the TypeScript encoder.
- `src/native/auto_push_record.rs` (+ `_tests.rs`, 9 tests).
  Parse and validate, tolerant read (absent or invalid is "no attempt"; other I/O errors propagate),
  `JSON.stringify`-identical encoding, candidate write with mode `0600` then rename, candidate removal on failure.
- `src/native/auto_push_single_flight.rs` (+ `_tests.rs`, 14 tests).
  Real-Git fixtures; the coordinator's wait is observed through a channel from a scoped thread.
  Covers the early join, the join after waiting for the owner lock (with the owner-token rule), the dead-owner takeover
  (planted lock with an exited pid), a failed push's output, and an uncovered tip.
- `src/native/auto_push.rs` (+ `_tests.rs`, 11 tests; `_concurrency_tests.rs`, 7 tests).
  Upstream and origin probes, detached HEAD note, push argv selection, output filter,
  failure reporting that never changes the commit's status.
  The push runs in a single pipe so stdout and stderr interleave; one trailing line break is stripped as `nano-spawn` does.
- `src/native/lib.rs`: four additive `pub mod` lines.

## Choices open to veto

- The auto-push function takes the real Git path, the directory and an explicit environment (`PushGit`).
  The incumbent's `nanoSpawn` inherits `process.env`; the integrator must pass the wrapper's child environment.
- Failures before the push decision (an unreadable repository, a Git that cannot start) return `Err` from `auto_push`.
  The incumbent throws there too, and the caller decides how to surface them.
- Terminal output goes to a `Write` sink, not directly to stderr, so tests can compare the exact text.
