# Repository review issue filing

## Purpose

Resume the repository-wide review of this repo without re-deriving its scope,
 decisions,
 or tooling.
 The user request:
 review the entire repository,
 open one GitHub issue per issue found,
 delegate the review to subagents,
 and do not limit issue volume.
 Updated 2026-10-17.

## Requirements

- [x] Partition the whole tracked tree into review scopes with no dead zones.
- [x] Build the issue filing pipeline (render,
 dedupe,
 paced `gh issue create`).
- [x] Validate one pilot reviewer output against the finding schema.
- [ ] Fan out the remaining review scopes to subagents.
- [ ] Deduplicate findings against each other and the 826 open issues.
- [ ] File one issue per distinct defect and report the issue numbers.

## Decisions recorded

- One issue per distinct defect,
 not per occurrence:
 the same defect at many sites is one issue listing every site.
 The user's "I don't care if you open 10k issues" grants volume,
 it does not buy duplicate issues.
- Issue bodies follow the tracker's evidence style (Problem,
 Evidence with verbatim quotes,
 Suggested action,
 Acceptance,
 Verification,
 Classification,
 Duplicate search),
 matching the existing open bug issues.
- Reviewers must probe cheaply (`rg`,
 `node -e`,
 `git log`) or mark `static:` verification;
 no builds,
 installs,
 or test runs inside review subagents.
- Reviewers write only their findings file;
 the main worktree stays untouched,
 which keeps this a deliberation request (report and issue writes only).
- Findings already covered by an open issue are skipped with `dupOfIssue` recorded,
 never re-filed.

## Rejected ideas

- Reviewer subagents filing issues directly:
 rejected for rate-limit bursts,
 partial-failure recovery,
 and inconsistent body shape;
 central pacing in `file-issues.ts` is resumable.
- Splitting the same defect into one issue per occurrence:
 rejected as tracker noise;
 the tracker's own bug issues aggregate identical sites.

## Open questions

- GitHub may rate limit bulk issue creation despite 2.5 s pacing.
 `file-issues.ts` backs off and records errors in `filed.jsonl`;
 a rerun continues where it stopped.
- Resolved 2026-10-17:
 the harness allows at most 8 active subagent children,
 so the fan-out runs in waves of 8.
 The pilot validated the finding schema (all fields present,
 25 findings from 155 files for `code-ssg-1`).
