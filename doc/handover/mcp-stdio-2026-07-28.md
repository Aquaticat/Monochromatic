### Open decision: concurrency and cancellation

`serve()` awaits each dispatch inline in the stdin read loop,
so a `run_in_vm` that takes 15 to 30 minutes blocks the loop:
the server cannot even read `notifications/cancelled` while it runs.
The spec says a cancelled request's associated processing **SHOULD** cease.

Fixing it properly appears to need concurrent dispatch, a serialized write queue,
an in-flight request table, and an `AbortSignal` reaching `ToolHandler`,
which changes a public signature all eight mvm tools implement.

Two hazards make this a decision rather than a chore:

-   Aborting `create_vm` or `update_templates` midway can strand a half-created VM
    or a half-built image, which is worse than letting it finish.
    Aborting `exec_in_vm` looks safe.
-   Concurrent dispatch lets two VM mutations interleave where the transport previously
    serialized them, which may open races in the mvm backend that did not exist before.

### Open decision: input schema validation

Nothing validates `arguments` against the advertised `inputSchema` before dispatch,
so a missing required field fails inside the handler rather than returning `-32602`.
`destroy_vm` now advertises `oneOf`/`not`/`const`, so a validator has to handle composition
keywords or state plainly that it does not.

Candidates: hand-roll the keyword subset actually used;
take an external dependency such as `ajv`, which cuts against this package having
exactly one workspace dependency and nothing external;
validate only `required` presence plus declared top-level primitive types as a documented subset;
or leave it to handlers.

## How to verify anything here

Both packages build, lint, type-check, and test through mise:

```sh
mise run //package/mcp/stdio:lint
mise run //package/mcp/stdio:buildAndTest
mise run //package/mcp/mvm:lint
mise run //package/mcp/mvm:buildAndTest
```

`buildAndTest` is required rather than `test:unit` alone:
both suites import the built artifact, so a source-only run tests stale output.

End-user verification goes through the client, not the test suite:

```sh
mise run //package/mcp/mvm:build
claude mcp get mvm
```

To see the actual wire exchange, register a tap that pipes stdio through to the real bin
while appending both directions to a log, then health-check the tap.
That is how the modern-path negotiation was confirmed;
the recipe is in the planning doc's verification section.

## Gotchas worth knowing before editing

-   **Read the full lint output, never a grep of its summary lines.**
    The rules in this repo carry ranked remediation instructions in the message body.
    Grepping cost a wrong fix once already: `no-nullish-union` names an empty object outright
    as a banned stand-in for absent, which a summary-line grep hides.
-   **Tests must import built output, not package source.**
    `require-eventual-artifact` enforces it.
    A behavior only reachable through a source symbol gets tested over stdio through the bin instead.
-   **Never let a `destroy_vm` test reach a real backend.**
    Every such case pins `backend` to a kind nothing resolves,
    so even an accepted call cannot destroy anything.
-   **`~/.claude.json` is rewritten by concurrent sessions.**
    Change MCP registrations with `claude mcp add`/`remove`, never by hand-editing the file.
-   **The client caches server era per process.**
    After changing protocol behavior, rebuild before re-running `claude mcp get`,
    or the health check exercises the previous binary.
