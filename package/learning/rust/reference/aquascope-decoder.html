Companion reference

Aquascope decoder for the opening diagram

Keep the opening diagram visible while reading this page. Aquascope is a separate teaching tool, not Rust syntax. It draws what Rust checks before code starts and what the program's data looks like while the code runs.

Read this page in order. “Words used by the decoder” explains the vocabulary that every later section relies on. No knowledge of Rust, computer memory, or systems programming is assumed.

Words used by the decoder

From source text to a running program

Source code
Text written by a programmer in a programming language. Rust source files normally end in .rs.

Example: let mut s = String::from("Hello world"); is one line of Rust source code.

TypeScript relationship: a .ts file is TypeScript source code.

Executable program
File that a computer can start and run. This page sometimes shortens “executable program” to “program.”

Example: main.rs is source text; a separate file produced from it is executable program.

TypeScript relationship: TypeScript is normally turned into JavaScript and run by Node.js or a browser; Rust normally produces an executable file ahead of time.

Compiler
Tool that reads source code before it can run. It either reports why the source is rejected or produces executable file that computer can start. Rust's compiler is named rustc.

Example: source text containing ??? where Rust expects code is rejected; compiler reports error instead of producing executable.

TypeScript relationship: tsc also checks source before running. Rust and TypeScript check different sets of rules; later sections explain Rust's additional checks.

Compile time
Period when the compiler is reading and checking source code, before the executable starts.

Example: compiler reporting unknown variable name is compile-time event.

TypeScript relationship: TypeScript type errors are also reported before the emitted JavaScript runs.

Runtime
Period after an executable has started and its instructions are running.

Example: the heap text Hello world shown at L1 exists at runtime.

TypeScript relationship: JavaScript executing inside Node.js or a browser is runtime behavior.

Parts of code

Keyword
Word reserved by a language for a particular purpose. A reserved word cannot be reused freely as a variable name.

Example: fn, let, and mut are Rust keywords.

TypeScript relationship: function, let, and class are TypeScript keywords.

Function and function call
Function is named section of code. Code inside function runs when function is called. A call is written with a function name followed by parentheses.

Example: greet(); calls a function named greet.

TypeScript relationship: TypeScript functions and calls have the same broad role.

main and automatic startup
main is special in a Rust executable. Rust-provided startup code runs first, then automatically makes required initial call to main. That startup code is supplied by Rust and is not written in main.rs. main is first function body written in this source that runs. Programmer does not add main(); at end of Rust file.

Example: starting this sample performs startup setup, enters fn main() { ... }, then runs line let mut s = ....

TypeScript relationship: the name main has no special behavior in TypeScript. A TypeScript function named main runs only if other code calls main().

Parameter and argument
Parameter is input name written in function definition. Argument is value supplied by particular function call.

Example: in fn double(number: i32), number is parameter and i32 means whole-number type; in double(5), value 5 is argument.

TypeScript relationship: TypeScript uses the same parameter and argument distinction.

Function body
Code enclosed by function's braces, { and }.

Example: everything between main's opening and closing brace is its body.

TypeScript relationship: TypeScript also uses braces around a normal function body.

Value
Actual piece of data handled by code.

Example: 5 is a number value; Hello world is text held by a String value.

TypeScript relationship: values have the same broad meaning in TypeScript.

Expression
Piece of code that produces a value.

Example: 2 + 3 is expression producing value 5.

TypeScript relationship: 2 + 3 is also TypeScript expression.

Statement
Complete action written in function body. Statements in this sample end with semicolons.

Example: 2 + 3; is one statement containing expression 2 + 3.

TypeScript relationship: TypeScript also has statements and commonly uses semicolons.

Type and field
Type names a category of values and the operations allowed on them. Field is named part stored inside a value of a type with multiple parts.

Example: String is a type; its expanded Aquascope picture shows an internal field named vec.

TypeScript relationship: TypeScript also checks types and object properties, but TypeScript types are removed before JavaScript runs; Rust types also determine how runtime data is represented.

Variable, variable declaration, and binding
Variable is programmer-chosen name for value while relevant code runs. Variable declaration creates that name. Rust documentation calls connection between name and current value a binding. After this definition, decoder may use “binding” for that connection.

Example: let score = 5; declares variable score and binds name score to value 5.

TypeScript relationship: this is closest to a TypeScript variable declaration; TypeScript programmers do not normally need “binding” as a separate term here.

Local variable
Variable declared inside one function body.

Example: s and hello are local variables inside main.

TypeScript relationship: a variable declared inside a TypeScript function is also local to that function body.

Assignment
Operation that puts a value under a variable name.

Example: in let score = 5;, = assigns value 5 to new variable score.

TypeScript relationship: = serves the same broad assignment role in TypeScript.

Mutation and mut
Mutation means operation alters current value reached through existing variable. Rust's let does not permit such alteration unless mut follows let.

Example: let mut score = 5; score = 6; changes current value reached through score from 5 to 6.

TypeScript relationship: TypeScript let permits later assignment without an extra keyword. Rust's mut has no direct TypeScript keyword equivalent.

Literal
Source-code spelling that directly represents a value.

Example: "Hello world" is a string literal; quotation marks mark its boundaries.

TypeScript relationship: "Hello world" is also a TypeScript string literal.

Text and computer memory

Memory
Space inside computer used to hold program data while program runs.

Example: Aquascope shows memory holding local variable s and text for Hello world.

TypeScript relationship: TypeScript programs also use memory, but JavaScript normally hides its layout.

Byte
Whole number from 0 through 255 used as a basic unit of computer memory.

Example: ASCII letter H has byte value 72.

TypeScript relationship: one element of a TypeScript Uint8Array holds one byte.

UTF-8
Rule for representing text as one or more bytes per written character.

Example: ASCII-only text Hello uses five UTF-8 bytes; character é uses two UTF-8 bytes.

TypeScript relationship: JavaScript's string model uses UTF-16 code units; encoding text as UTF-8 bytes normally requires an API such as TextEncoder.

String
Rust type for UTF-8 text whose contents can grow or shrink after creation. The type tracks where its bytes are, how many bytes are text, and how much room is reserved.

Example: String::from("Hi") creates a String containing two UTF-8 bytes.

TypeScript relationship: TypeScript string values cannot be modified internally; an expression such as text += "!" produces a different string value. Rust String has no exact TypeScript string mirror.

Method
Function attached to type and called with dot syntax on value of that type.

Example: let s = String::from("Hi"); let n = s.len(); creates s, calls len, and binds byte count 2 to n without changing s.

TypeScript relationship: TypeScript object and class methods use similar dot-call syntax.

Allocation, deallocation, and buffer
Allocation is block of memory reserved for a value. Deallocation returns that block so it can be reused. Buffer is allocated block reserved to hold a sequence of items such as bytes.

Example: at L1, s's buffer is an allocation holding eleven text bytes; at L4, drop(s) causes that allocation to be deallocated.

TypeScript relationship: JavaScript normally deallocates objects automatically through garbage collection, meaning the runtime later reclaims objects that code can no longer reach through any variable.

Stack and frame
Aquascope uses Stack for active function calls. Each call gets frame that lists its local variables. This is learning model; compiler may represent local values differently without changing Rust rule being taught.

Example: main's frame lists local variable s at L1.

TypeScript relationship: JavaScript engines also track active function calls, but TypeScript does not expose their memory layout.

Heap
Memory area used for allocations whose size is chosen while the program runs.

Example: the eleven text bytes for Hello world appear in Aquascope's Heap box.

TypeScript relationship: JavaScript objects use heap memory, but TypeScript does not expose their addresses or cleanup timing.

Pointer and pointee
Pointer is value that identifies another location in memory. Pointee is data at the location identified by the pointer. Aquascope draws pointer as dot and draws connector to its pointee.

Example: s's dot connects to byte H at the start of its heap allocation.

TypeScript relationship: JavaScript engines use hidden references for objects, but ordinary TypeScript has no explicit memory-address pointer.

Length, capacity, and metadata
Length says how many positions currently contain part of value. Capacity says how many positions fit in current allocation before larger allocation is needed. Metadata means small values that describe other data; pointer, length, and capacity describe String's bytes.

Example: len 11 and cap 11 mean all eleven available byte positions are occupied.

TypeScript relationship: arrays expose length, but TypeScript does not expose JavaScript array capacity.

Rust access and cleanup rules

Ownership and owner
For each allocation, Rust tracks value currently responsible for cleanup. That value is allocation's owner. When owner ends, Rust performs cleanup at that point.

Example: String value reached through s owns heap buffer; when that String ends, Rust deallocates buffer.

TypeScript relationship: ordinary TypeScript does not assign one variable responsibility for cleanup; garbage collection has no direct ownership equivalent.

Move
Move transfers value and its ownership from one variable or function input to another. Old variable is not “empty”; compiler rejects later reads through it.

Example: after let b = s; for a String, b can be used but compiler rejects later use of s. Calling drop(s) similarly moves value from s into drop.

TypeScript relationship: there is no direct TypeScript move. Assigning object to another TypeScript variable leaves both variables usable and pointing to same object.

Reference and borrow
Reference is compiler-checked pointer that lets code access data owned elsewhere. Reference does not become responsible for destroying that data. Borrow means using & to create this temporary access; resulting value is reference. Compiler limits what owner can do while reference will still be used.

Example: let hello = &s[0..5]; borrows first five bytes from s.

TypeScript relationship: TypeScript has no borrow operator and no compile-time rule that temporarily blocks the original variable this way.

Slice and &str
Slice is reference to continuous part of existing sequence plus its length. &str is Rust type for string slice. It does not own or copy bytes it refers to.

Example: hello has type &str, starts at H, and has length 5.

TypeScript relationship: string.slice returns a new string value, not compiler-checked borrowed view, so it is not direct mirror.

drop
Rust function that receives value, ends that value immediately, and performs its cleanup. Passing owned value to drop moves it, so original variable becomes unusable.

Example: drop(s); ends String and deallocates its heap buffer at L4.

TypeScript relationship: delete removes object property and does not destroy object; ordinary TypeScript has no direct operation that immediately frees object's memory.

Undefined behavior
Situation for which Rust provides no promise about result. Reading from deallocated memory is one example. Compiler rejects ordinary Rust source when its checks can see such invalid read.

Example: if code read hello after old allocation had been deallocated, it would try to read bytes that no longer belong to string.

TypeScript relationship: ordinary TypeScript does not expose deallocated-memory reads; it has no direct language-level equivalent of this Rust memory error.

Copyable TypeScript anchor example 
function main(): void {
  let text = "Hello world";
  text += "!";
}

const first = { text: "Hello" };
const second = first;
second.text += "!";

main(); // main has no automatic meaning in TypeScript

This one example shows three contrasts: TypeScript calls main explicitly, let needs no mut, and both first and second remain usable after assignment.

Every piece of the code panel

fn main() {
    let mut s = String::from("Hello world");
    let hello = &s[0..5];
    s.push_str("!");
    drop(s);
}

fn main() { ... }

fn
Keyword that starts Rust function definition.

Example: fn greet() {} defines function named greet.

main
Special function whose initial call is performed automatically when executable starts.

Example: launching this executable enters main; Rust source does not contain separate main(); call.

()
Empty parameter list, meaning main declares no input parameters.

Example: a function with one parameter could begin fn greet(name: String).

{ }
Braces marking start and end of function body.

Example: all four sample statements are between main's braces.

let mut s = String::from("Hello world");

let
Keyword starting variable declaration. Declaration creates binding between variable name and value.

Example: let score = 5; binds name score to value 5.

mut
Keyword allowing later assignment to this variable and operations that alter its current value. mut is written as part of one variable declaration. Another variable needs its own mut if code will alter value through that other name.

Example: s.push_str("!") changes s's text from Hello world to Hello world! and byte length from 11 to 12. It may reuse current buffer or replace full buffer with larger allocation. Without mut, compiler rejects this exact call.

s
Programmer-chosen variable name. Letter has no built-in Rust meaning.

Example: later statements use same name in s.push_str("!") and drop(s).

=
Assignment operator connecting new variable to value produced on right.

Example: value produced by String::from(...) becomes value reached through s.

String
Type of new growable UTF-8 text value.

Example: at L1, this String owns buffer holding Hello world.

:: and from
:: selects function attached to type itself rather than to existing value. from is selected function's name.

Example: String::from("Hi") creates new String from literal "Hi".

"Hello world"
Literal supplying source text. Quotation marks mark boundaries and are not part of text. String::from copies literal's eleven bytes into owned buffer shown by Aquascope.

Example: heap cells at L1 show H through d, not quotation marks.

;
Mark ending statement.

Example: each of four statements in sample ends with semicolon.

let hello = &s[0..5];

hello
New local variable whose type is inferred as &str.

Example: expanded L2 view shows hello with pointer and length 5.

&
Borrow operator that creates reference instead of transferring ownership.

Example: hello can read five bytes, but s's String still owns their buffer.

[ ]
Indexing brackets selecting part of value.

Example: brackets apply range 0..5 to s's text.

0..5
Range starting at byte position 0 and stopping before byte position 5.

Example: included positions 0 through 4 spell Hello.

The sample never reads hello later. Compiler therefore treats borrow as finished before next statement. Example: if let count = hello.len(); were added after push_str, borrow would still be needed there and compiler would reject earlier push_str call.

s.push_str("!");

.
Dot selecting method on value to left.

Example: s.len() selects method len on s.

push_str
String method that appends bytes from string slice. Its input type is &str; literal "!" has that string-slice type, so method reads literal's byte without taking ownership of literal. It adds exclamation-mark byte, increasing length from 11 to 12. Because current capacity is only 11, this Aquascope run obtains capacity-22 allocation, copies eleven existing bytes, appends new byte, and deallocates old allocation. Capacity 22 is observed here, not guaranteed growth rule.

Example: before call, s contains Hello world; after call, it contains Hello world!.

("!")
Parentheses contain argument passed to method. Argument is one-character string literal.

Example: literal supplies exclamation-mark byte visible at end of heap at L3.

drop(s);

drop
Function ending supplied value immediately and performing cleanup.

Example: at L4, heap buffer is gone because drop ended String.

(s)
Argument passed to drop. Passing owned String moves it out of s and into function; s cannot be used afterward.

Example: after drop(s);, compiler rejects later s.push_str("?"); because s's value was moved into drop.

What changes from L1 to L4

L1: after String::from("Hello world")
StackHeapExact effect
main frame contains s with pointer, length, and capacity metadata. Eleven bytes spell Hello world. New String owns buffer containing copy of literal's bytes.

Example: expanded view reports len 11 and cap 11.

L2: after let hello = &s[0..5]
StackHeapExact effect
s still owns buffer; hello holds pointer and length 5. Same eleven bytes remain. No text byte is copied; hello describes first five existing bytes.

Example: hello reads as Hello.

L3: after s.push_str("!")
StackHeapExact effect
s points to current allocation; hello's old target is invalid. Twelve bytes spell Hello world!. This Aquascope run replaced full capacity-11 allocation with capacity-22 allocation.

Example: program remains valid because it never reads hello after its creation. Rust rejects version that reads hello after push_str.

Capacity 22 is observed result of this run, not Rust language promise. Code may rely on enough capacity for current text, but not on doubling.

L4: after drop(s)
StackHeapExact effect
s is moved-out; displayed pointers are invalid. String buffer is absent. drop ended owning String and deallocated buffer.

Example: compiler rejects later code that reads s, calls method on s, or passes s to another function.

Every label in the binocular picture

Standard library means reusable types and functions shipped with Rust. Example: String, Vec, and drop come from Rust's standard library. Binocular picture exposes private details inside that library. Their names and nesting can change with Rust version. Learn them only well enough to decode this picture.

A wrapper is value whose job is to contain another value while adding a rule. Example: NonNull wraps pointer and adds rule that pointer cannot be null. Null means special pointer value that points nowhere.

Containment at L1

  • variable s: String
    • field vec: Vec<u8>
      • field buf: RawVec<u8>
        • field inner: RawVecInner
          • field ptr: Unique<u8>
            • field pointer: NonNull<u8>
              • field pointer: pointer dot ●
          • field cap: UsizeNoHighBit / 11
      • field len: 11
vec
Lowercase private field inside String holding its UTF-8 bytes through Vec<u8>.

Example: for String::from("Hi"), this field's Vec has length 2 and points to buffer containing bytes H and i.

Vec<u8>
Vec is Rust list type whose length can change. <u8> says each list element has type u8, Rust byte-sized number type.

Example: vec![72_u8, 105_u8] constructs Vec<u8> containing byte values for Hi.

Macro
Rust construct that compiler expands into other Rust code during compilation. Macro calls use exclamation mark after name.

Example: vec![1, 2, 3] is call to macro named vec!.

TypeScript relationship: TypeScript has no direct language feature with Rust's macro-call syntax.

vec!
Macro that constructs Vec; it is different from lowercase field vec and uppercase type Vec.

Example: vec![1, 2, 3] constructs list with three number values.

u8
Rust type for whole number from 0 through 255, commonly one byte.

Example: 72_u8 is byte value for ASCII H; suffix _u8 tells Rust its type.

buf
Short for buffer. Field inside Vec that owns reserved memory block.

Example: at L1, buf owns room for eleven bytes.

RawVec
Private standard-library layer recording buffer pointer and capacity. Outer Vec separately records length.

Example: screenshot places RawVec around inner, while len 11 remains outside it.

inner
Field name meaning next private layer inside RawVec.

Example: inner contains fields ptr and cap.

RawVecInner
Private standard-library type grouping pointer and capacity used by RawVec.

Example: at L1, its pointer reaches heap text and its capacity is 11.

ptr
Short for pointer. Field holding pointer wrapper.

Example: following nested value inside ptr reaches heap byte H.

Unique
Private pointer wrapper telling standard-library code to treat allocation as owned through this path.

Example: Unique<u8> is wrapper on route from s to its byte buffer.

pointer inside Unique
Field containing next wrapper, NonNull. It is not second allocation.

Example: expanded box reads Unique → pointer → NonNull around same route to heap.

NonNull
Private pointer wrapper guaranteeing contained pointer is not null, meaning not “points nowhere.” It does not by itself guarantee target has not been deallocated.

Example: at L1, NonNull contains pointer dot leading to live text buffer.

pointer inside NonNull
Deepest displayed field containing actual pointer mark ●.

Example: Aquascope connector starts at this dot and ends at first heap byte.

cap
Short for capacity. Field records how many bytes fit before another allocation is needed.

Example: cap 11 is full when len 11; adding one byte requires more room.

usize
Rust type for non-negative whole numbers used as lengths and index positions. Largest possible value depends on computer where program runs.

Example: end position 5 in 0..5 can be represented as usize.

UsizeNoHighBit
Private number wrapper used for capacity. Bit means one binary digit, either 0 or 1; this wrapper only accepts numbers whose highest bit is 0.

Example: UsizeNoHighBit / 11 wraps capacity number 11.

Type / value
Aquascope display notation, not Rust source syntax. Text before slash is type and text after slash is current value.

Example: UsizeNoHighBit / 22 means wrapper type currently contains 22.

len
Short for length. For String, it counts UTF-8 bytes currently used.

Example: len changes from 11 to 12 after adding !; one-character text é has byte length 2.

Do not memorize this wrapper chain. Stable idea is only: String owns heap bytes and records pointer, length, and capacity.

Every mark in the R, W, O permission picture

This is compile-time picture, not runtime memory. A place is specific data location named by code: whole variable, field, indexed element, or target reached through reference. Permission is Aquascope's letter for operation compiler currently allows at one place and one source position.

Example: s is place for whole String; s[0..5] is place for selected text range. Same place can have different permissions before and during borrow.

TypeScript relationship: TypeScript has no direct R, W, O permission model.

R: Read
Permission to read data.

Example: evaluating s.len() reads s without changing its text.

W: Write
Permission to mutate data.

Example: s.push_str("!") needs W because text differs afterward.

O: Own
Permission to move or drop owned data. Letter means “own,” not “object.”

Example: drop(s) needs O because it moves and ends String.

+R, +W, +O
Place gains shown permission after source line.

Example: let mut s = ... creates mutable initialized variable, so picture can show +R+W+O.

Slashed letter
Place loses shown permission after source line.

Example: while reference to s's data will be used later, s loses W and O.

‒
Place lacks that permission and line did not change absence.

Example: variable declared without mut can show dash where W would appear.

Filled expected letter
Operation needs permission and place has it.

Example: s.len() can show filled R when reading is allowed.

Hollow expected letter
Operation needs permission but place lacks it, so compiler reports error.

Example: push_str can show hollow W when later reference use keeps s borrowed.

Permission example without new syntax

fn main() {
    let mut word = String::from("Hello");
    let first = &word[0..1];
    let count = first.len();
    word.push_str("!");
}
  1. word starts with RWO.
  2. Reference first temporarily removes W and O from word.
  3. first.len() is last use of reference, so borrow ends after this statement.
  4. word regains W and O, so push_str is allowed.

Rejected example: move word.push_str("!") before let count = first.len();. Later read through first keeps borrow active, so word lacks W where push_str needs it.
