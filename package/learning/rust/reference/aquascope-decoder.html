Aquascope decoder for the opening diagram

Keep the opening diagram visible while reading this page. This reference labels the Rust code, controls, memory picture, expanded internals, and compile-time permission letters.

Aquascope is a visualization tool, not part of the Rust language. It can show a simulated program execution or the compiler's permission model. The opening page displays concepts before the book teaches them, so use this decoder rather than trying to infer every box unaided.

First reading: stay in the simple view

The useful picture is simple: a local variable named s holds information about text, while the text's bytes live in a separate heap allocation. A pointer connects the two.

  1. Match each L badge beside the code with the diagram carrying the same badge.
  2. Read Stack, the local variables, pointer dots, and Heap.
  3. Ignore the binocular button until the simple view makes sense.
  4. Treat RawVec and similar names as optional implementation details, not required vocabulary.

Example: at L1, s is in the main stack frame, and its pointer leads to the heap bytes spelling Hello world.

Aquascope answers two different questions

Runtime or Interpret view
This view asks, “What values and allocations exist after this statement runs?” It contains the Stack, Heap, pointers, and L1 through L4 snapshots.

Example: after s.push_str("!"), the runtime view shows the heap text as Hello world!.

Compile-time or Permissions view
This view asks, “Which operations would the Rust compiler permit at each source location?” It contains R, W, and O. These permissions are compiler reasoning, not values stored in memory while the program runs.

Example: a variable declared with let mut normally receives read, write, and own permissions, displayed as RWO.

The program at the top

fn main() {
    let mut s = String::from("Hello world");
    let hello = &s[0..5];
    s.push_str("!");
    drop(s);
}

First line around the body

fn
Keyword that declares a function.

Example: fn greet() {} declares a function named greet.

main
Conventional entry function where this executable starts. It is also the frame name shown inside Stack.

Example: the first statement executed in this program is inside main.

()
Function parameter list. Empty parentheses mean this function declares no parameters.

Example: main() has no named input between the parentheses.

{ }
Braces enclose the function body.

Example: all four statements in the sample are inside main's braces.

let mut s = String::from("Hello world");

let
Keyword that creates a local variable binding.

Example: let score = 5; creates a local variable named score.

mut
Allows the bound value to be changed through this variable. Without it, calling a method that changes s would be rejected.

Example: let mut score = 5; score = 6; changes score.

s
Programmer-chosen variable name. It is short for “string” here, but Rust gives the letter no special meaning.

Example: s.push_str("!") later uses this same variable.

=
Assigns the expression on the right to the new binding on the left.

Example: in let score = 5;, the value 5 is assigned to score.

String
Rust's owned, growable, UTF-8 text type. “Owned” means this value is responsible for eventually freeing its heap allocation.

Example: String::from("Hi") creates growable text containing Hi.

::
Selects an item associated with a type or module. Here it selects the function from associated with String.

Example: String::new() calls another function associated with String.

from
Conversion function used here to make an owned String from a string literal.

Example: String::from("Hi") converts the literal "Hi".

"Hello world"
String literal embedded in the program. The quotation marks delimit the text and are not stored as characters.

Example: this literal contains eleven ASCII bytes, including one space.

;
Ends this statement.

Example: each of the four statements in main ends with a semicolon.

let hello = &s[0..5];

hello
New local variable name. It will refer to part of the text owned by s.

Example: in this run, hello refers to the five bytes spelling Hello.

&
Borrow operator. It creates a reference that can temporarily access data without taking ownership of it.

Example: let whole = &s; borrows the whole String.

[ ]
Indexing syntax. With a range inside, it selects a slice of the string.

Example: s[0..5] selects bytes from index 0 up to, but not including, index 5.

0..5
Half-open range. It includes 0 and excludes 5. These are byte positions for a string slice.

Example: positions 0 through 4 in Hello world spell Hello.

Reference
Non-owning pointer produced by a borrow. The referent must remain valid while the reference is used.

Example: hello is a reference to the first five bytes owned by s.

Slice
View into a contiguous part of existing data. A string slice tracks a starting pointer and byte length.

Example: the expanded L2 view shows hello with a pointer and len 5.

s.push_str("!");

.
Method-call syntax. It asks Rust to call a method using the value on the left.

Example: s.len() calls the len method on s.

push_str
String method that appends a string slice. It may need a larger heap allocation when current capacity is full.

Example: appending "!" changes Hello world to Hello world!.

"!"
One-character string literal passed as the method argument.

Example: the heap gains an exclamation-mark byte at L3.

drop(s);

drop
Standard function that takes ownership of a value and destroys it immediately. Destroying this String frees its heap allocation.

Example: after drop(s), L4 has no heap text and s is unusable.

(s)
Function argument. Passing the owned String moves it into drop.

Example: a later println!("{s}") would be rejected because s was moved.

Controls and framing

L1, L2, L3, L4
Snapshot labels added by Aquascope. They are not Rust syntax. Each badge beside the source corresponds to a memory picture with the same badge.

Example: L2 beside the borrow matches the picture where both s and hello exist.

Dashed outer border
Boundary of the embedded Aquascope widget.

Example: the code and all four snapshots sit inside one dashed border.

Copy icon
Copies the displayed Rust code.

Example: pressing it copies the four statements so they can be pasted elsewhere.

Eye icon
Reveals or hides helper source lines that the book chose to conceal. It does not change the program's meaning.

Example: a hidden surrounding fn main() { ... } can be revealed without changing a snapshot.

Binocular icon
Toggles between the compact value view and concrete standard-library internals.

Example: compact s ● expands into String, Vec, RawVec, and pointer wrappers.

Horizontal scrollbar
Moves across a diagram wider than the available page. It carries no Rust meaning.

Example: the concrete view may require scrolling to see both stack internals and heap bytes.

Labels and marks in the simple runtime view

Stack
Aquascope's model of active function frames and their local variables. Real optimized machine code may keep some values in processor registers instead.

Example: the main frame contains local variables s and, at L2, hello.

main
Function frame belonging to the running main call. A frame maps local variable names to their current values.

Example: s appears inside the box headed main.

Heap
Memory region used for dynamically sized allocations that can outlive an individual expression. The screenshot says Heap, not Help.

Example: the bytes spelling Hello world are in the heap at L1.

●
Pointer value. A pointer describes where another value is located. The arrow or connector leads to its pointee, meaning the value it points to.

Example: the dot stored by s points to the first byte H in the heap allocation.

Arrow or connector
Visual relation from a pointer to its pointee. It is not data copied between the boxes.

Example: hello's connector targets only the first five bytes of Hello world.

⦻
Pointer whose old pointee is no longer allocated. Aquascope uses it to show invalid memory. The program causes undefined behavior only if it later tries to use such a pointer.

Example: after reallocation at L3, hello's old target has been freed, so Aquascope shows ⦻.

Faded or striped value
Value that has been moved and can no longer be used through that variable.

Example: s is striped at L4 because drop(s) moved it.

One box per character
Compact display of the string's bytes in order. The source text is ASCII, so each displayed character occupies one byte in this example.

Example: the first five boxes contain H, e, l, l, o.

Read the four snapshots

L1: after creating the String
StackHeapChange
main contains s, whose compact value is a pointer. Eleven bytes spell Hello world. String::from allocated and copied the literal's text.

Example: in the expanded run, len is 11 and cap is 11.

L2: after borrowing a slice
StackHeapChange
s still owns the text; hello holds a non-owning pointer and length 5. The same eleven bytes remain allocated. hello now refers to the range spelling Hello.

Example: no character is copied to create hello; the slice describes existing bytes.

L3: after appending the exclamation mark
StackHeapChange
s points to the current allocation; hello's old target is shown as invalid. Twelve bytes spell Hello world!. The full eleven-byte allocation grew to capacity 22 in this Aquascope run.

Example: this program is still valid because it never uses hello after the borrow statement. If a later statement read hello, Rust would reject the mutation of s.

The observed change from capacity 11 to 22 is not a language promise. Rust guarantees sufficient capacity, but code must not depend on a particular growth factor.

L4: after dropping s
StackHeapChange
s is moved and both pointer displays are invalid. The string allocation is gone. drop destroyed the owner and freed its allocation.

Example: attempting s.push_str("?") after drop(s) would be a compile-time use-after-move error.

The binocular view, decoded

The nested rectangles show containment. A capitalized label is generally a type name, a lowercase label is generally a field or variable name, and the deepest number or dot is a value.

Example: String is a type, vec is a field inside it, and 11 is a value held by length or capacity metadata.

Containment path shown at L1

  • variable s contains a String
    • field vec contains a Vec<u8>
      • field buf contains a RawVec<u8>
        • field inner contains a RawVecInner
          • field ptr contains a Unique<u8>
            • field pointer contains a NonNull<u8>
              • field pointer contains the pointer dot ●
          • field cap contains UsizeNoHighBit / 11
      • field len contains 11

Every concrete label

vec
Private field inside String that stores its UTF-8 bytes as Vec<u8>. This lowercase field is different from both the Vec type and the vec! macro.

Example: for String::from("Hi"), the vec field manages bytes H and i.

Vec<u8>
Growable sequence whose elements have type u8. Vec is short for vector, not a mathematical direction in this context.

Example: vec![1_u8, 2_u8] creates a two-element Vec<u8>.

vec!
Macro that constructs a Vec. The exclamation mark is part of macro-call syntax. It does not appear as a label in the concrete screenshot, but distinguishing it prevents three similar names from blending together.

Example: let digits = vec![1, 2, 3]; constructs a vector with three elements.

u8
Unsigned eight-bit integer type. A String stores UTF-8 encoded bytes of this type.

Example: ASCII H is stored as the u8 value 72.

buf
Field inside Vec that manages its allocated buffer. “Buffer” means a region reserved for elements.

Example: at L1, buf manages space for eleven bytes.

RawVec
Internal standard-library helper that owns an allocation and tracks its capacity, but leaves the outer Vec to track how many elements are initialized. It is not a type ordinary Rust code needs to use.

Example: buf: RawVec owns the allocation for Hello world, while sibling field len records eleven used bytes.

inner
Field inside RawVec containing the allocation details shared across element types. The name means only “implementation nested inside this wrapper.”

Example: the screenshot's inner contains both ptr and cap.

RawVecInner
Internal standard-library type that groups a buffer pointer, capacity, and allocator information.

Example: at L1, its pointer targets the heap text and its capacity value is 11.

ptr
Abbreviation of “pointer.” This field stores the pointer wrapper used to find the allocation.

Example: following ptr's nested dot leads to the heap byte H.

Unique
Unstable standard-library wrapper around a non-null raw pointer. It signals that the containing abstraction owns the referent and must uphold unique ownership rules.

Example: the Unique<u8> inside s's buffer represents ownership of the byte allocation.

pointer field inside Unique
Field that contains the next pointer wrapper, NonNull. It is another wrapper layer, not another heap allocation.

Example: opening the Unique box reveals pointer: NonNull around the same pointer dot.

NonNull
Raw-pointer wrapper whose value is guaranteed not to be the null address. Non-null does not by itself guarantee that the pointed-to allocation remains alive.

Example: at L1, NonNull contains the dot leading to the live Hello world allocation.

pointer field inside NonNull
Deepest displayed field holding the actual pointer value visualized as ●.

Example: Aquascope draws a connector from this dot to the first heap byte.

cap
Abbreviation of “capacity,” meaning how many elements fit in the current allocation before growth is required. For a String, those elements are bytes.

Example: cap 11 is full when len 11; appending one byte requires more capacity.

UsizeNoHighBit
Internal integer wrapper whose highest bit must remain zero. RawVec uses it for capacities restricted to the supported range. This is an implementation detail, not a Rust keyword or public collection concept.

Example: UsizeNoHighBit / 11 wraps the capacity value 11.

usize
Unsigned integer type sized for indexing and memory sizes on the current target platform. It is the ordinary integer underneath UsizeNoHighBit.

Example: let index: usize = 5; can hold the end index used by 0..5.

Type / value
Aquascope notation in the concrete display, not Rust source syntax. Text before the slash names a wrapper type; text after it is the contained value.

Example: UsizeNoHighBit / 22 means a UsizeNoHighBit currently containing 22.

len
Abbreviation of “length,” meaning how many elements are currently initialized and part of the value. For this ASCII String, it is also the visible character count.

Example: len changes from 11 to 12 after appending !.

Do not memorize the wrapper chain. RawVec, RawVecInner, Unique, and UsizeNoHighBit are standard-library internals and may change between Rust versions. The stable learning target is that a String manages a pointer, a length, a capacity, and UTF-8 bytes in a heap allocation.

The permission letters R, W, and O

Permissions belong to the compile-time view. They describe operations the borrow checker permits on a place, meaning a storage location expression such as a variable, field, index, or dereference.

Example: x, values[0], and *reference are all places because each can identify stored data.

R: Read
Permission to read data, including copying a copyable value to another location.

Example: let x = 5; let y = x; reads x to copy 5 into y.

W: Write
Permission to mutate data at a place. A variable normally receives it only when declared with mut.

Example: let mut x = 5; x = 6; uses W permission on x.

O: Own
Permission to move or drop owned data. O means “own,” not “object.”

Example: drop(s) requires O because it moves and destroys the String.

+R, +W, or +O
The place gains that permission after the marked source line.

Example: let mut x = 5; initializes x, so the diagram can show +R+W+O.

Slashed permission
The place loses that permission after the line.

Example: borrowing &s temporarily removes W and O from s while the reference remains in use.

‒
The place does not have that permission, and the line did not change that fact.

Example: let x = 5; without mut can show a dash in the W position.

Filled expected letter
Operation needs the permission and the place has it.

Example: reading x displays a filled R when x is readable.

Hollow expected letter
Operation needs the permission but the place lacks it, corresponding to a compiler error.

Example: mutating a borrowed vector can show a hollow W because the borrow removed write permission.

Worked borrow example

fn main() {
    let mut values = vec![1, 2, 3];
    let first = &values[0];
    println!("{first}");
    values.push(4);
}
  1. values starts with RWO because it is initialized and mutable.
  2. Creating first borrows from values, temporarily removing W and O.
  3. println! is the last use of first, so the borrow ends.
  4. values regains W and O, allowing push.

Example of rejection: move values.push(4) before println!. The push needs W, but values remains borrowed until first's later use, so Rust rejects the program before runtime.

What to retain from this opening page

  • Aquascope is a tool with separate runtime and compile-time visualizations.
  • L1 and similar badges join a source statement to a state snapshot.
  • A String manages heap bytes through pointer, length, and capacity metadata.
  • A reference such as hello points to existing data without owning it.
  • Growing a full string may replace its allocation and invalidate pointers to the old allocation.
  • drop(s) consumes the owner and frees its heap allocation.
  • R, W, and O mean read, write, and own in compile-time permission diagrams.
  • The concrete wrapper chain is optional implementation detail.
