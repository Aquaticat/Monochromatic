Q1: What should separate surfaces in light mode?

The unfolded Pixel 9 Pro Fold is rendered at 852×883dp with the settled picker and transport on the left, a 16dp seam, and tracks on the right. Only the light-surface hierarchy changes.

Pros
  • Uses MD3’s intended tonal hierarchy.
  • Looks calm and keeps attention on content.
  • Uses one separation mechanism.
Cons
  • Picker, transport and track surfaces are close in value.
  • Separation may weaken on poor panels or at low brightness.

My readSecond choice. Quiet and readable, but less immediate than 1c.

Pros
  • Separation stays explicit across panels and brightness levels.
  • Most directly mirrors dark mode’s structure.
Cons
  • Borders around panes, controls and rows create grid noise.
  • Light mode feels more administrative than the other treatments.

My readThird choice. Robust, but it spends too much visual ink.

Pros
  • Creates the clearest hierarchy with little linework.
  • Keeps the track list quiet while separating picker and transport.
  • Uses a hairline only where the rail needs one.
Cons
  • Mixes tonal separation with one outline.
  • The dim window gives light mode a heavier surrounding field.

My readFirst choice. Best hierarchy for the amount of visual ink used.

Ranking: 1c > 1a > 1b 1c beats 1a because its pane hierarchy survives at a glance. 1a beats 1b because its softer separation avoids turning every row and region into a box.

Q2: How prominent should true-peak values be in light mode?

Each track-pane detail uses the measured 418×883dp half of the unfolded display. The row stays two lines and keeps duration plus true peak. Only emphasis changes.

Pros
  • Uses one simple rule in both themes.
  • Keeps supporting text subordinate to track titles.
  • Leaves every true-peak value available.
Cons
  • Duration and true peak receive equal emphasis despite different jobs.
  • The values recede in the light comparison.

My readSecond choice. Clear enough, but harder to scan.

Pros
  • Makes true-peak values easy to scan across the folder.
  • Preserves every value without adding a column.
  • The weight difference is visible without competing with titles.
Cons
  • Introduces two treatments within one supporting line.
  • Repeated bold values add some visual texture.

My readFirst choice. Scannable without structural cost.

Pros
  • Produces the quietest list.
  • Keeps the current track’s value visible.
Cons
  • Prevents comparison across tracks.
  • Hides already-computed information from its expected location.
  • Conflicts with the settled two-line row content.

My readReject. The visual calm is not worth losing the values.

Ranking: 3b > 3a > 3c 3b beats 3a because it makes true peak scannable without structural cost. 3a beats 3c because retaining all values preserves the settled row contract.
