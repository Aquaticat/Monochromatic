How much total separation should opposing information need?

E2 already keeps meaning-bearing app marks off the approximate physical crease. Its remaining floor is a total left-to-right separation between opposing information, not extra blank surface or a margin on each side. The rule is gap ≥ max(min_padding, physical crease width). Surfaces and hit regions may cross. This question chooses the independent floor, not a layout redesign. The selected Search A, folder browser, deck and D56/D57 remain settled. No new device or IME experiment was done.

Choose a physical-unit policy

P10 · 10mm independent minimum (Recommended)

Pros

  • Requires at least 2.5mm of combined clearance beyond this device's approximate 7.5mm crease.
  • Sets a stable physical total-separation floor if a later device has a narrower crease.

Cons

  • The measured 11.35mm box proxy is not ink or a same-height opposing pair; compliance remains unverified.
  • Could require a different layout in unmeasured states or devices.

My read: Recommend as a moderate independent floor, without asserting that the current art already passes. This 10mm is a proposed separation target, not the superseded 10mm estimate of the crease itself.

P0 · No independent floor, crease width alone

Pros

  • The current target's effective threshold stays at its approximately 7.5mm physical crease width.
  • Does not impose an invented global floor beyond the already accepted meaning-off-crease rule.

Cons

  • A future narrower crease would lower the effective total-separation threshold.
  • There is no independent buffer for opposing information across the fold.

My read: Sound if E2 should track only the actual obstruction, rather than promise a separate baseline. Numerically this option sets min_padding = 0mm in E2, not a new component padding value.

P12 · 12mm independent minimum

Pros

  • Requires at least 4.5mm of combined clearance beyond this device's approximate crease.
  • Provides a stricter target if stronger visual separation is worth possible layout responses.

Cons

  • Exceeds the 11.35mm projected box-gap proxy, but actual painted distance and nearest same-height pair remain unmeasured.
  • A state that fails this target would require a visible response; no such response has been built or validated.

My read: Choose if the stricter physical floor is intentional even though current-state fit is unproven; do not infer automatic truncation or layout changes from the proxy alone.

Ranking: P10 > P0 > P12. P10 exceeds the physical crease while setting a bounded independent target; P0 is second because it honors only the known obstruction rather than creating a stricter unverified target; P12 is third because it exceeds even the available projected box-gap proxy without a built alternative. This is a policy ranking, not a visual fit test. All options still require app information to remain outside the physical crease; none mandates symmetric left/right clearance.
