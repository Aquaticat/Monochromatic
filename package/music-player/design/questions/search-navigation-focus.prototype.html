Music player · design-only Search behavior · Pixel 9 Pro Fold

What happens when Search gains and loses focus?

Selected Search A keeps the actual folder browser and playback deck beside the right-side query/results on the unfolded Fold; the cover has one full-width Search page. Back/query/Clear remain one integrated header. D59 accent highlights, D60 direct-name scope, D61 mixed order and E2's information floor are fixed. This logic-only prototype explores page entry, focus, Clear, Back, re-entry and scroll position. It is not an Android screen, input method, native accessibility test or production Search implementation.

All keyboard labels on this page are simulated state. No Gboard or debug IME was opened. The accepted D56 cover viewport brought the final row above a measured bottom keyboard after scrolling; hiding and refocusing required another swipe in that prototype. D56 did not select the extra swipe. The five preferences below are independent: change one at a time, then use the guided cases or free-play controls to see the result. Initial radio checks are recommended previews, not decisions.

Independent choices, with my ranking

Entry edit focus

When Search opens

Ranking: E1 > E2. E1 starts the explicitly requested Search task with fewer actions; E2 buys an unobstructed first view but delays typing.

System Back with keyboard visible

One system Back gesture

Ranking: B1 > B2. B1 preserves the active result context before exiting; B2 is quicker to leave but easier to invoke unintentionally. The visible Back arrow always returns to the player under D47.

Clear and edit focus

After the × clears text

Ranking: C1 > C2. C1 changes only what Clear names (the query); C2 anticipates the next action but changes visible layout too. Both keep Search open.

Reopen after returning to player

Next Search visit

Ranking: R1 > R2. R1 treats the player-to-Search action as a new task; R2 favors rapid return to the prior task.

Refocus without changing query

Results position after keyboard returns

Ranking: S1 > S2. S1 treats refocus as a viewport change, not a new search; S2 makes the user retrace the list. A changed query resets to top in this demonstration only.
