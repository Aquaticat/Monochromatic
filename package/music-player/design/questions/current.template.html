Decision one: structural surface reach

R1 · recommended

Stable black structure

Keep the folder canvas, rail, track canvas, and deck on the accepted fixed black ladder. Android still generates component accents, text, and outlines.

  • Pros: structural surface colors remain fixed across wallpaper changes; preserves B2 literally.
  • Cons: generated neutral tint stays out of large structural surfaces.
R2

Zoned dynamic structure

Keep both content canvases black. Use generated surfaceContainerLow for the letter rail and deck.

  • Pros: adds bounded Material You surface expression without tinting either content canvas.
  • Cons: wallpaper changes the visual weight of the rail and deck.
R3

Tonal folder structure

Keep the track canvas black. Apply generated low, standard, and high containers across the folder canvas, rail, and deck.

  • Pros: gives the strongest system-personalized pane hierarchy.
  • Cons: uncontrolled palette color occupies the complete folder pane and competes with true black.

Ranking: R1 > R2 > R3. R1 beats R2 because every meaningful component accent still follows Android while structural surface colors stay stable. R2 beats R3 because it confines generated surfaces to bounded regions instead of letting an uncontrolled palette dominate the folder pane.

Decision two: current-row neutral source

C1 · recommended

Fixed soft neutral

Keep the accepted current row at fixed #0A0A0D plus bold title, independent of structural surface reach.

  • Pros: preserves one calm current-state treatment under every wallpaper and contrast setting.
  • Cons: the row container itself does not inherit Android's generated neutral hue.
C2

Dynamic soft neutral

Use Android-generated surfaceContainerLow plus the same bold title, independent of structural surface reach.

  • Pros: keeps the semantic Material role synchronized with the user's current palette and contrast.
  • Cons: gold, magenta, and high-contrast environments visibly change the row's weight and hue.

Ranking: C1 > C2. C1 beats C2 because D36 chose a calm neutral state rather than saturated current-row color; controls already provide dynamic personalization without making current-state weight wallpaper-dependent.

Analysis and recommended additions

Wallpaper robustness

Every candidate changes controls, selected accents, text, and outlines with Android. R1 alone fixes structural surfaces; R2 and R3 intentionally add generated neutral tint.

True-black expression

R1 keeps the folder canvas, rail, and track canvas black. R2 keeps both content canvases black. R3 keeps the track canvas black but makes the folder canvas dynamic.

Current state

Every candidate retains a neutral current-row container plus bold title. C1 fixes its color; C2 accepts Android's generated neutral hue and contrast response.

Evidence boundary

These captures establish palette-dependent appearance. They do not establish live wallpaper refresh because each debug candidate is relaunched after Android roles settle.

Implementation follow-through

Later implementation should follow system theme changes live, retain a baseline dark fallback below Android 12, use generated outline for the dark rail boundary, and regression-test wallpaper changes without restarting the app.
