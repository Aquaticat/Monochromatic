Dark mode and Android dynamic color are required. This matrix asks only how far wallpaper-derived roles should reach into the accepted unfolded screen. It does not authorize production implementation.

Strategies

A · recommended

Stable black ladder

Keep the accepted fixed black surface ladder. Use Android dynamic roles for Pause, Open, selected mode, folder indicator, text, and outlines.

  • Pros: hierarchy and current-row neutrality stay invariant across wallpaper changes; preserves B2 literally.
  • Cons: large structural surfaces do not inherit Android's generated neutral tint.
B

Zoned dynamic containers

Keep both content canvases black. Use generated surfaceContainerLow for the letter rail, deck, and current row.

  • Pros: adds Material You expression without tinting either content canvas.
  • Cons: wallpaper changes the visual weight of three structural or state regions.
C

Tonal folder pane

Keep the track canvas black. Apply generated low, standard, and high containers across the folder pane, rail, and deck.

  • Pros: gives the strongest system-personalized pane hierarchy.
  • Cons: uncontrolled wallpaper color occupies a whole pane and competes with true black.

Ranking: A > B > C. A beats B because wallpaper still changes every meaningful accent while the accepted neutral hierarchy remains stable. B beats C because it confines generated surfaces to bounded regions instead of letting an uncontrolled palette dominate the complete folder pane.

Analysis and recommended additions

Wallpaper robustness

A changes controls and selected accents in every row without changing structural weight. B and C also tint surfaces, most visibly under Gold Vibrant and Magenta Expressive.

True-black expression

A keeps both panes and the rail black. B keeps both content canvases black. C keeps the track canvas black but makes the complete folder pane dynamic.

Current state

Every candidate retains a neutral current-row container plus bold title. A makes that neutral invariant; B and C accept the generated neutral hue.

Implementation follow-through

Later implementation should follow system theme changes live, retain a baseline dark fallback below Android 12, use generated outline for the dark rail boundary, and regression-test wallpaper changes without restarting the app.
