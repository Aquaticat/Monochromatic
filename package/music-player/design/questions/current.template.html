What still deserves design work

  1. Scope: a global hotkey is settled, but it is not decided whether the surface runs commands only or also finds folders and tracks.
  2. Category control: merged results can organize themselves into groups or expose explicit Folders, Tracks, and Commands controls.
  3. Fold placement: generic 720dp docked search would cross the fold, so every viable prototype keeps interactive controls outside the 24dp center spacer.
  4. Ambiguous track names: a track match needs its folder name, duration, and true-peak context at selection time.
  5. Before typing: a blank command surface needs useful recent actions rather than an empty panel.
  6. Input and accessibility: results need a visible and announced count, arrow-key navigation, Enter activation, and visible shortcuts where they exist.

Nine command-bar prototypes

Every prototype keeps baseline Material 3, real Android system bars, dynamic light color, and the fold-safe 24dp center spacer. Docked variants leave the accepted screen visible under a scrim, right-pane variants preserve its folder pane, and split full-screen variants replace both panes.

My recommendation and full ranking

Recommend 2B: Unified with automatic groups in the right pane. It gives one fast entry point enough vertical room for a large library, keeps the folder pane visible, and never places a target on the fold. Use 2A when preserving the track pane is more important than showing more results.

  1. 2B · Unified, right pane. Best balance of scope, capacity, context, and fold safety.
  2. 2A · Unified, docked. Below 2B because preserving the track list costs result height.
  3. 3B · Explicit scope, right pane. Below 2A because most queries should not require category interaction.
  4. 3A · Explicit scope, docked. Below 3B because filters take space from an already short result surface.
  5. 2C · Unified, split full-screen. Below 3A because taking both panes is too disruptive for routine invocation.
  6. 1B · Commands only, right pane. Below 2C because it leaves library navigation in a second search system.
  7. 3C · Explicit scope, split full-screen. Below 1B because it combines maximum interruption with maximum control state.
  8. 1A · Commands only, docked. Below 3C because its narrow scope and short result area both limit discovery.
  9. 1C · Commands only, split full-screen. Below 1A because the largest takeover serves the least content.

Worth adding regardless of the winning prototype

  • Show folder name, duration, and true peak on every track result.
  • Show keyboard shortcuts on command results and support arrows plus Enter.
  • Show recent commands or destinations before typing.
  • Show and announce the result count whenever results update.
  • Highlight the matching substring without changing the selected-row state.
  • Adapt to conventional full-screen focused search on the compact cover screen.
