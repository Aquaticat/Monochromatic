What still deserves design work

  1. Missing required control: the settled design requires a volume icon and vertical popover, but the accepted capture contains neither.
  2. Button placement: the icon can preserve or disturb the centered now-playing title and playback controls depending on where it joins the transport block.
  3. Level precision: slider position communicates relative level, while an optional percentage makes the exact value visible.
  4. Mute access: a named Mute action is discoverable, but makes the popover taller and may duplicate icon-button behavior.
  5. Occlusion: the anchored popover should cover as little folder content as possible while keeping its trigger visible.
  6. Prototype boundary: these captures decide placement and visible content, not the production technique used to implement a vertical slider.
  7. Later state sheet: keyboard focus, hover, long labels, and simultaneous playing-plus-focus states still deserve a separate review of this same screen.

Nine refinements of the current screen

Every prototype keeps the accepted screen and opens the missing required volume control. Rows change only the icon's position. Columns change only the popover readout. The slider remains vertical, anchored, built from Material components, and wholly inside the left pane in every cell.

Row 1 · icon in the now-playing header

The volume icon sits at the header's trailing edge while the title remains centered.

Cons

My recommendation and full ranking

Recommend 2B: volume at the playback row's trailing edge with a percentage. It keeps volume beside playback, preserves the centered previous, pause, and next group, and adds precise feedback without the taller Mute action. Use 1B if visual symmetry matters more than semantic grouping.

  1. 2B · Playback row, percentage. Best balance of meaning, precision, and compactness.
  2. 2C · Playback row, percentage + Mute. Below 2B because the named action makes the popover taller and may duplicate the icon.
  3. 1B · Header, percentage. Below 2C because it separates volume from related playback actions.
  4. 1C · Header, percentage + Mute. Below 1B because the extra action adds occlusion without fixing that separation.
  5. 2A · Playback row, slider only. Below 1C because correct placement does not compensate for losing exact feedback.
  6. 1A · Header, slider only. Below 2A because it loses both semantic proximity and numeric feedback.
  7. 3B · Dedicated row, percentage. Below 1A because another permanent row costs more than the precise readout gains.
  8. 3C · Dedicated row, percentage + Mute. Below 3B because it combines the extra row with the tallest popup.
  9. 3A · Dedicated row, slider only. Below 3C because it pays the extra-row cost without either explicit addition.

Worth adding to the selected volume treatment

  • Announce the current percentage whenever keyboard, wheel, touch, or hardware-key input changes it.
  • Let arrows and the pointer wheel adjust the slider while the popover has focus.
  • Show a desktop tooltip naming Volume before the popover opens.
  • Restore the last nonzero level when leaving a muted state.
  • Keep the popover open while consecutive hardware-key changes arrive, then dismiss it without moving layout.
