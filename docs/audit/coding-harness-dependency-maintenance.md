### Manifest posture observed so far

- Aider uses Python packaging with dynamic dependencies from `requirements.txt`.
  `requirements.txt` is generated by `uv pip compile` and pins resolved dependencies exactly.
  Source intent is in `/tmp/agent/harness-aider-20260624/requirements/requirements.in`.
- Gemini CLI uses npm workspaces with `package-lock.json` and many exact dependency versions in root `package.json`.
  It also has explicit overrides for some packages.
- Codex is primarily a Rust workspace with a small Node maintenance layer.
  Root `package.json` uses pnpm with several exact `resolutions` and some ranged specs.
- OpenCode uses Bun workspaces and a root catalog with many exact dependency versions,
  several patched dependencies,
  and no obvious update bot config yet.
- Goose is a Rust workspace with `Cargo.lock` and semver-compatible workspace dependency specs.
  It contains a few explicit exact pins with comments explaining why.
- Crush is a Go module with `go.mod` and `go.sum`.
  It uses Dependabot for Go modules and GitHub Actions.
- ForgeCode uses Rust plus npm.
  Rust dependencies in root `Cargo.toml` mostly use semver-compatible versions,
  and npm benchmark/eval dependencies use ranges in root `package.json`.

## Current tentative reading

The comparison is shaping up as a split between two different dependency-maintenance styles:

- `pi`, Gemini CLI, Aider, and OpenCode lean conservative or lockstep through exact pins,
  lockfiles, catalogs, overrides, or generated requirements.
- Codex, Goose, Crush, and ForgeCode show more explicit update automation,
  with ForgeCode currently the strongest automation signal because it combines Dependabot and Renovate automerge.

This does not yet prove any candidate is a better coding harness overall.
It only indicates some candidates may have better dependency-update automation than `pi`.
`pi`'s exact pins appear intentional rather than neglectful.
